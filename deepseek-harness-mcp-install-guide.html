DeepSeek Harness + Packet Tracer MCP — Install Guide

This guide covers two things:

  1. Installing DeepSeek Harness (from deepseek.com/en/harness)
  2. Using DeepSeek Harness to install the Packet Tracer MCP server — you copy-paste the llms-install instructions into DeepSeek Harness chat, and Harness installs uv and the MCP server for you (from Mats2208/MCP-Packet-Tracer/llms-install.md)
What is DeepSeek Harness? DeepSeek Harness (dsh) is an open-source agent harness from DeepSeek AI, built on Cordis's "everything is a plugin" architecture. It runs as a desktop app or as a web UI from code. It is currently in public preview worldwide.

Part 1 — Install DeepSeek Harness

Option A: Desktop app (easiest)

  1. Go to https://www.deepseek.com/en/download/.
  2. Click Download Desktop.
  3. Install the downloaded package for your OS.
  4. Launch DeepSeek Harness and sign in.

Option B: Run from npm (Web UI)

Prerequisite: Install Node.js first.
  1. Open a terminal.
  2. Run: npx @deepseek-ai/dsh web
  3. The Web UI starts at http://127.0.0.1:3080 by default and opens in your default browser.
  4. To run without opening a browser, pass --no-open.

Option C: Run from source

  1. Clone the repository: git clone https://github.com/deepseek-ai/deepseek-harness.git
  2. Enter the directory: cd deepseek-harness
  3. Install dependencies: pnpm install
  4. Build artifacts: pnpm run build
  5. Start the web UI: pnpm dsh web

pnpm run build prepares the repository artifacts; pnpm dsh web uses those built artifacts without rebuilding.

Developer preview notice: DeepSeek Harness is in developer preview and iterating rapidly — there will be compatibility-breaking changes. Review the safety notice in the repository before running from source.

Part 2 — Use Token Harbor free models in DeepSeek Harness

Before installing MCP tools, set up a free model API key so Harness can run agent steps without paid credits.

  1. Go to tokenharbor.ai and sign in (free account, no card required).
  2. Open the dashboard and copy your Universal Key (format: thk_live_...).
  3. In DeepSeek Harness, open model/provider settings and add an OpenAI-compatible provider with:
    • Base URL: https://tokenharbor.ai/v1
    • API key: your thk_live_... key
  4. Select a model ID that ends with :free (for example, any free model shown in Token Harbor's model list), then save and use that model in your chat session.
Important: Token Harbor shows the full key once. Store it in your password manager and never paste it into public chats, screenshots, or repos.
Tip: If your client supports environment variables, store the key as TOKEN_HARBOR_API_KEY and reference it from settings instead of pasting plain text.

Part 3 — Let DeepSeek Harness install the Packet Tracer MCP server

The Packet Tracer MCP server lets an AI agent (Claude Code, OpenCode, Codex, Cursor, Claude Desktop, or VS Code Copilot) control Cisco Packet Tracer. DeepSeek Harness provides the agent environment; the MCP server plugs into your client.

The short version: once DeepSeek Harness is running, copy the block in Step 0 — What to paste into DeepSeek Harness below and paste it into the Harness chat. Harness will read the llms-install instructions and carry out every step — installing uv, registering the MCP server in your client, installing the skill, and placing the Packet Tracer extension — so you don't have to run anything by hand.

Prerequisites before you paste:
  • Cisco Packet Tracer 8.2+ must be installed (9.0 recommended). If it is not installed, download it from https://www.netacad.com/resources/lab-downloads (free with a NetAcad account).
  • DeepSeek Harness must be running (desktop app, or npx @deepseek-ai/dsh web, or from source).
  • Token Harbor key configured in Harness if you want to run this on free models.

Step 0 — What to paste into DeepSeek Harness

Copy this entire block and paste it into your DeepSeek Harness chat:

Use my configured Token Harbor provider and select a model ID ending with :free for this task.
Install the Packet Tracer MCP server for me by following the instructions at https://github.com/Mats2208/MCP-Packet-Tracer/blob/main/llms-install.md.

Do everything in order:
1. Check whether `uv` is installed (`uv --version`); if not, install it (macOS/Linux: curl -LsSf https://astral.sh/uv/install.sh | sh ; Windows PowerShell: powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex").
2. Register the MCP server in my agent client with the command `uvx packet-tracer-mcp --stdio` (on Windows: `uvx --from "packet-tracer-mcp[ui]" packet-tracer-mcp --stdio`). I am using [Claude Code / OpenCode / Codex / Cursor / Claude Desktop / VS Code] — pick the matching registration from llms-install.md step 2.
3. Install the skill with `uvx packet-tracer-mcp install-skill` into my user-level skills folder.
4. Download the MCP Control Center extension (.pts) from the MCP-Packet-Tracer releases and place it in Packet Tracer's extensions folder (per-platform paths from llms-install.md step 4).
5. When Packet Tracer asks to enable the new script module "MCP-Control-Center", I will click Yes myself — that is the only step I do by hand.
6. Restart my agent session and verify with `pt_bridge_status` that the bridge is active and connected.

Report back after each step, and ask me before doing anything system-wide.
Why paste this instead of doing it yourself: DeepSeek Harness is an agent — it reads the llms-install.md instructions, installs uv (which downloads a suitable Python by itself, so you never touch the system Python), registers the MCP server, installs the skill, and places the extension. The only thing Harness cannot do for you is click "Yes" in Packet Tracer's enable dialog (Step 5) — that requires a real user.

What DeepSeek Harness will do (reference — copied from llms-install.md)

These are the steps Harness performs on your behalf. You can watch them in the Harness chat.

Step 1 — Make sure uv is installed

The MCP server runs through uv, which downloads a suitable Python by itself. Nothing gets installed into the system Python.

Check with uv --version. If it is missing, install it:

macOS / Linux curl -LsSf https://astral.sh/uv/install.sh | sh
Windows (PowerShell) powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
A shell opened before the install will not see uvx yet. If uvx is "not found" right after installing, use its full path: ~/.local/bin/uvx (macOS/Linux) or %USERPROFILE%\.local\bin\uvx.exe (Windows).

Step 2 — Register the MCP server in your client

The server command is uvx packet-tracer-mcp --stdio.

Windows only: use uvx --from "packet-tracer-mcp[ui]" packet-tracer-mcp --stdio instead — the [ui] extra lets the MCP open Packet Tracer's device windows and capture them (UI mode exists only on Windows). Put the same --from "packet-tracer-mcp[ui]" in front of packet-tracer-mcp in every command and JSON args below.
ClientRegistration command / config
Claude Code claude mcp add --scope user --transport stdio packet-tracer -- uvx packet-tracer-mcp --stdio
PowerShell (Windows): claude mcp add --scope user --transport stdio packet-tracer "--" uvx --from "packet-tracer-mcp[ui]" packet-tracer-mcp --stdio
Check: claude mcp list → packet-tracer: … ✓ Connected
Codex codex mcp add packet-tracer -- uvx packet-tracer-mcp --stdio
OpenCode Add to ~/.config/opencode/opencode.json (merge, do not overwrite other keys):
{ "mcp": { "packet-tracer": { "type": "local", "command": ["uvx", "packet-tracer-mcp", "--stdio"], "enabled": true } } }
Cursor / Claude Desktop / any JSON client Add to ~/.cursor/mcp.json (Cursor) or your client's MCP config:
{ "mcpServers": { "packet-tracer": { "command": "uvx", "args": ["packet-tracer-mcp", "--stdio"] } } }
VS Code (Copilot) .vscode/mcp.json 
{ "servers": { "packet-tracer": { "type": "stdio", "command": "uvx", "args": ["packet-tracer-mcp", "--stdio"] } } }
If the client cannot find uvx, put its full path (from Step 1) in command.

Step 3 — Install the skill (required)

Without the skill the MCP works halfway — you would guess device models, port names and Script-Engine methods instead of discovering them. Install it into your own skills folder.

  • Claude Code and OpenCode: uvx packet-tracer-mcp install-skill (→ ~/.claude/skills/packet-tracer)
  • Codex: uvx packet-tracer-mcp install-skill --dest ~/.agents/skills
  • Other agents: uvx packet-tracer-mcp install-skill --dest <your user-level skills folder>

Step 4 — Put the Packet Tracer extension where PT finds it

Packet Tracer scans its own extensions folder when it starts and asks the user to enable any new script module there. Copy this project's extension (MCP Control Center, not PTBuilder) into that folder, inside a subfolder of its own.

macOS
macOS
APP="$(ls -d /Applications/Cisco\\ Packet\\ Tracer*/Cisco\\ Packet\\ Tracer*.app | tail -1)"
mkdir -p "$APP/Contents/extensions/MCPControlCenter"
curl -L -o "$APP/Contents/extensions/MCPControlCenter/MCPControlCenter.pts" \\
    https://github.com/Mats2208/MCP-Packet-Tracer/releases/latest/download/MCP-Control-Center.pts
Verified: macOS, no admin needed.
Windows
Windows

The folder is C:\Program Files\Cisco Packet Tracer <version>\extensions\, which needs administrator rights. Windows will ask for permission once; then run from PowerShell (adjust the version folder you find):

$pt = (Get-ChildItem "C:\Program Files" -Directory -Filter "Cisco Packet Tracer*" | Select-Object -Last 1).FullName
$tmp = "$env:TEMP\MCPControlCenter.pts"
Invoke-WebRequest -OutFile $tmp https://github.com/Mats2208/MCP-Packet-Tracer/releases/latest/download/MCP-Control-Center.pts
Start-Process powershell -Verb RunAs -Wait -ArgumentList "-Command", "New-Item -ItemType Directory -Force '$pt\extensions\MCPControlCenter' | Out-Null; Copy-Item '$tmp' '$pt\extensions\MCPControlCenter\MCPControlCenter.pts' -Force"
Linux
Linux

PT is a single AppImage in /opt/pt, so there is no extensions folder to copy into.

  1. Download the .pts to the user's Downloads folder.
  2. PT must start at least once: the user accepts the EULA by running packettracer in a terminal (from the menu no window appears).
  3. On Ubuntu 26.04 it also needs sudo apt install libopengl0 libts0t64 (ask the user first).
Verified: Linux on Ubuntu 26.04 + PT 9.0.1.
Fallback: If copying is not possible, download the file to the user's Downloads folder and have them add it with Extensions → Scripting → Configure PT Script Modules → Add….

Step 5 — The user enables it (one click — the only step Harness cannot do)

The only thing you do by hand is clicking Yes when Packet Tracer asks to enable the extension.

  1. Open (or restart) Cisco Packet Tracer. PT only looks for new modules when it starts, so if it was already open it must be closed completely first.
  2. A dialog says "Cisco Packet Tracer has detected a new script module. Do you want to enable this script module?" showing Name: MCP-Control-Center by Mateo Andres Soto Gareca — click Yes.
  3. The MCP Control Center window opens and connects by itself (on later starts: Extensions → MCP BUILDER).
  4. Verified on Windows 11 and macOS with PT 9.0.1. Wait until you see it connected.

Step 6 — Restart and verify

MCP servers and skills load when the session starts: restart your agent session (in Claude Code: exit and run claude again). Then, in the new session:

  1. Call pt_bridge_status — it must say the bridge is active and connected.
  2. Run a first test: "Create a network with 1 switch and 2 PCs, deploy it to Packet Tracer and ping between the PCs."
If pt_bridge_status says Packet Tracer is not connected: check that the MCP BUILDER window is open, close and reopen it once (the token is created the first time the server runs), and call it again.
